## 1. 三步工作流

每个条目都必须走完这三步才算完成，跳步即视为未完成。

### 第 1 步 · 需求

**输入**：主人的指示 + 参考图编号。

**我要产出**（缺一项就动手 = 耍赖）：

1. **做什么** —— 一句话说明改哪个界面 / 哪个文件
2. **长什么样** —— 元素清单、参考图编号、要填的数值
3. **验收点** —— 什么现象算做完了，能被截图或日志证明

**准入**：条目三要素齐了才进开发。
**准出**：主人认可需求表述。对参考图的解读有歧义时，先复述一遍再动手。

### 第 2 步 · 开发

**顺序**（铁律见 `.trae/rules/project_rules.md`）：

0. **动代码前先查 [`docs/踩坑记录.md`](踩坑记录.md)** 有没有同类坑。本项目 UI 的三个高频坑：
   §8 根节点漏绑 script、§10 子节点也要挂脚本且一个 .cs 只能一个类、§11 事件驱动的初值要手动推一次。
1. 布局写进 `.tscn`（UI 优先建独立场景，禁止代码硬编码坐标）
2. 逻辑写进 `.cs`（一个 `.cs` 只挂一个类，根节点和槽位节点都要挂）
3. 事件回调**首行** `GD.Print($"[类名] 方法名 called")`、**末行** `... completed`
4. 挂进父场景 / 接到现有管理器上

**准出**：`dotnet build` 0 错。新增 `.tscn` 引用的资源必须真实存在。

### 第 3 步 · 验证

**我做**（后台跑，不抢主人鼠标）：

- 用 `Scenes/Dev/DevScenario.tscn` + 预设进场景，`background: true`
- **主动把关键截图和日志原文贴进聊天**，不只汇报「通过了」
- 断言按条目里的「验证」栏执行

**主人做**（通过后）：

- 我开**可见模式**的调试场景准备器窗口，主人自己点、自己验证、**自己关**，我不 stop
- 主人反馈后我改，改完重跑第 3 步

**准出**：截图证据 + 主人确认。**没贴截图就不算验证过。**

**四种验证形态**（每个条目的「验证」栏必须指明用哪几种）：

| 形态 | 含义 |
| :--- | :--- |
| 视觉 | 截图与参考图对照，看布局/配色/层级对不对 |
| 行为 | 点哪里 → 发生什么，是否符合预期 |
| 数据 | 日志里的具体数值（如 `携带地图血量进入战斗: 125/125`） |
| 回归 | 相关旧流程没被改坏（如打完 BOSS 还能回图） |
