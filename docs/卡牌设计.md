## 1. 现状盘点（已实测量过）

### 1.1 已经有了什么

`Data/character_cards.json` 里 **60 张卡**（12 可玩角色 × 5，BOSS 卡已按主人指示删除），
每张都带：卡名 / 类型 / 费用 / 是不是攻击 / 伤害 / 护盾 / 抽牌 / 能量 / 增益 / 减益 / 怒气成长 / 等级系数，
并且**每张都有独立的插画**（`Assets/Cards/card_<cardId>.svg`）。
**D29 已经把这张表接进战斗**（此前队伍卡组是代码硬编码的，12 张特殊技全是空牌）。

### 1.2 为什么还是「不够丰富」——缺口

| # | 缺口 | 证据 |
| :--: | :--- | :--- |
| 1 | **机制太扁平**：60 张可玩卡只用到 8 种效果（伤害 / 护盾 / 抽牌 / 能量 / 中毒 / 虚弱 / 群体 / 力量）。羊的 3 张特殊卡**全是护盾**、狗的 3 张特殊卡**全是护盾+能量**、猪的 3 张特殊卡**全是护盾** —— 换角色只是换数字，不是换玩法 | 见 §4 |
| 2 | ~~**名字撞车 3 处**~~ → ✅ **已解决**：改 3 张卡的名字（不删卡），现在**组内重名 = 0、跨角色重名 = 0** | `rat_defense` 狡兔三窟→**鼠洞藏**（原本是兔子的名字，抄错了）· `tiger_attack` 猛虎下山→**虎牙咬**（特色牌「猛虎下山」保留）· `ox_attack` 野蛮冲撞→**牛牙咬**（特色牌「蛮牛冲撞」保留）。名字取自**项目自己的旧命名**（`角色名+牙咬` / `角色名+洞藏`），没有新造 |
| 3 | **升级系统是空壳**：`Card.Level` 1~6、伤害每级 +20%、`CardUpgradeInfo.AddExp` 都写好了，但**全项目没有任何地方给卡牌加经验**（`AddExp` 零调用点）→ 「满级卡牌」现在在游戏里**根本到不了** | `Card.cs` / `CardLevelSystem.cs` 有实现，`AddExp` 无调用者 |
| 4 | **升级也不涨伤害**：战斗走的是 `card.Damage`（绝对值），等级系数 `CalculatedDamage` 只在有 `LinkedAttributes` 时才被卡面用上 → **卡面和战斗的数值来源不是同一个函数**（今天两边数值恰好相同，纯属巧合） | `BattleManager.ApplyCardDamage` 用 `card.Damage`；`DescriptionGenerator` 用 `CalculatedDamage` |
| 5 | **没有存档**：卡牌等级 / 经验无处可存 → 每场战斗都从 1 级开始 | README §7 已列为待办 |

### 1.3 等级数值口径（满级截图的反推依据）

现成的成长公式在 `CardLevelSystem.cs`：

| 类型 | 公式 | 6 级 = 1 级的几倍 |
| :--- | :--- | :--- |
| 伤害 / 护盾（属性联动） | `值 × 系数 × (1 + 0.2 × (等级-1))` | **×2.0** |
| 抽牌 / 能量 / 增益数值（固定值） | `基础 + 每级 × (等级-1)` | 基础 + 5×每级 |
| 怒气 | `5 + 每级 × (等级-1)`（战斗实际发 15/10，见 D30） | — |

### 1.4 参考截图读出来的卡牌模型（波吕克斯，主人放入的 10 张）

主人放入 `docs/screenshots/人物_波吕克斯/`（人物列表 / 卡牌总览 / 卡牌总览(满级) / 卡牌1~5 / 卡牌2 升级界面 / 天赋1），
从中读出的**参考游戏的卡牌模型**，跟我们现状的差距：

| 项 | 参考游戏的做法 | 我们的现状 | 差距 |
| :--- | :--- | :--- | :--- |
| **数值口径** | **卡牌数值 = 角色属性 × 百分比**（升级界面直接写「护盾：防御力*18%」） | 卡牌写死**绝对值**（`damage: 8`） | ⚠️ **模型级不同** → 数据表要改成百分比 |
| **等级成长** | 护盾：防御 156×18% = 29（Lv5）→ 32（Lv6）；伤害：攻击 182 → 打击 37（Lv6） | 伤害/护盾 `×(1+0.2×(级-1))`；固定值 `基础+每级×(级-1)` | 百分比每级怎么涨，要用截图反推 |
| **狂气** | 打击 Lv6 = 10；防御 Lv5 = 9 → Lv6 = 10 | `CalculateRageGain` = **5 + 每级×(级-1)** | ✅ **完全一致** —— 我们的公式本来就是照它反推的 |
| **卡牌类型** | **指令** / **灵知觉醒**（觉醒卡带「打出时 + 弃牌阶段后」多段触发，还能改别的卡的伤害） | 只有 `isAttack` + `style` | 缺「觉醒卡」这类机制卡 |
| **保留** | ⚠保留（打出后不弃） | `isRetain` ✅ | 已有 |
| **卡组结构** | **打击 + 防御 + 3 张专属**（每个角色**各自**两张基本卡：名字通用，但条目 / 词条 / 运行时实例各自独立） | attack + defense + special×3 ✅ 结构一致 | 我们的名字各有风味（见 §1.2-2 的取舍） |
| **角色属性** | 体质 / 攻击 / 防御（**没有暴击**） | attack / defense / constitution / **crit / critDamage** | 暴击是**我们多出来的**，参考图没有 |
| **角色等级** | 角色本身有等级（波吕克斯 Lv.74/74） | 无角色等级 | 差距 |
| **卡牌升级** | 消耗**材料 + 金币**，界面能「当前 / 下一级」对比 | 无升级入口（`AddExp` 零调用点） | 差距（也是「满级」够不到的原因） |
| **技能** | 「无罪的圣裁」= AoE 546 + 让下张指令卡享受「苦痛救赎」+ 把 1 张「圣心」置入手中 | 必杀技（怒气满 30 释放） | 概念对应，缺「往手里塞特殊卡」「给下一张牌加效果」 |
| **满级预览** | 卡组界面有「满级预览」按钮，一键看满级数值 | 无 | 差一个小功能（对我们很有用：正好用来核对截图） |

**最关键的一条**：参考游戏里**卡牌不写死伤害/护盾，而是写百分比**，数值由**角色属性**算出来。
这与主人说的「每个角色的数值确实也不同，但**这只影响造成伤害时的公式计算**」完全对上 ——
也就是我们的数据表要从「绝对值」改成「百分比」（`damage: 8` → `damagePercent: 20`），角色属性进公式。

## 5. 角色机制 · 天赋 · 数值（数据模型）

三层分开，**职责不混**：

| 层 | 放哪 | 内容 |
| :--- | :--- | :--- |
| **卡牌层** | `Data/character_cards.json` | 卡名 / 费用 / 基础数值 / 效果引用（effectIds）/ 等级系数 |
| **角色层** | 新表 `Data/character_mechanics.json` | 每个角色：**机制 1 条** + **天赋 N 条** + 参数 |
| **数值层** | `Data/characters.json`（已有）+ `CharacterAttributes` | 攻击 / 防御 / 体质 / 暴击… —— **只参与伤害公式** |

### 5.1 伤害公式（统一成一个函数，卡面与战斗共用）

```
最终伤害 = 卡牌基础伤害 × 等级系数 × 角色伤害系数
    等级系数   = 1 + 0.2 × (等级 - 1)        （6 级 = ×2.0）
    角色伤害系数 = 角色当前攻击 ÷ 角色基础攻击   （今天没有攻击加成 → 系数 = 1）
最终护盾 = 卡牌基础护盾 × 等级系数
```

**为什么这么定**：

1. **今天的数值一个都不变**（角色伤害系数 = 1）→ 不会打破已经玩过的手感。
2. **角色的数值真正进公式** → 天赋 / 装备 / 刻印给的攻击加成会立刻反映在伤害上（主人说的
   「角色数值只影响造成伤害时的公式计算」）。
3. **等级系数终于生效** → 现在战斗走 `card.Damage` 绝对值，**升级不涨伤害**（§1.2-4），这个坑顺手修。
4. **卡面与战斗共用同一个函数** → 文案与实现**不可能**不一致（D29 立的规矩）。

> ❓ **要主人点头的一点**：我用的是「角色攻击 ÷ 角色基础攻击」这种**比例系数**，
> 保证现有数值不变。另一种更常见的做法（参考游戏那种）是「**角色攻击 × 卡牌系数**」，
> 那样数值会整体变（需要重新配一遍所有卡的基础值）。我建议先用前者（数值不变、只让加成生效）。

#### 6.2.2 三条结论（其中两条我们早就对上了）

1. **等级系数与我们完全一致** ✅
   参考的 20%（Lv6）/ 18%（Lv5）正好等于 `10% × (1 + 0.2×(L−1))` ——
   和我们的 `CardLevelSystem.CalculateCoefficient` 逐项吻合。

2. **参考游戏是「向上取整」（ceil），我们是「四舍五入」** ⚠️ **待主人拍板**
   四个数全部对不上 1 点，但**换成 ceil 就全部对上**：

   | | 参考卡面 | 四舍五入（我们） | 向上取整 |
   | :-- | :--: | :--: | :--: |
   | 打击 182×20% | 37 | 36 | **37** ✓ |
   | 防御 156×18% | 29 | 28 | **29** ✓ |
   | 明灯灼魂 182×80% | 146 | 146 | **146** ✓ |
   | 离垢的审判 182×140% | 255 | 255 | **255** ✓ |

   我们当前用 `Mathf.RoundToInt`。改成 ceil 会让**所有卡牌数值普遍 +0~1**（对标参考游戏更准，但会动现有数值）。

3. **怒气口径与参考游戏不一致** ⚠️ **待主人拍板**
   参考：打击 Lv6 = **10**、防御 Lv5 = **9** → 公式 `5 + 每级×(级−1)`（我们数据表的 `rageGainPerLevel=1` 正好是这个）。
   我们：固定 **15**（攻击牌）/ **10**（防御牌），与卡牌等级无关（`RageManager`）。
   → 参考是「等级越高怒气越多」，我们是「固定值」。

> 所以这个卡牌配置至少应该有**统一的策划表的配置**，
> 还有**角色查看时候的配置**，以及**战斗的时候真正生成时候的配置**。」

### 7.1 三层配置：一份策划表，两个派生视图

```
① 策划层（静态 · 唯一真相源）Data/character_cards.json
   名称 / 费用 / 类型 / 词缀 / 效果 / 每级数值 / 专属说明
   —— 策划只改这一份
        │
        ├─▶ ② 角色查看层（预览 · 不进战斗）
        │     策划层 + 角色属性（攻/防/体质）
        │     → 渲染「这个角色这张卡在 Lv.N 的数值与文案」
        │     角色一览的「卡牌总览」走这条
        │
        └─▶ ③ 战斗实例层（运行时 · 每场战斗每张卡一份）
              策划层 + 角色属性 + **当前状态修正**（buff 改费用 / 增减词缀 / 改数值）
              → 实际打出去的那张卡
```

**为什么必须分三层**：角色查看层和战斗实例层的**数值必须同源** ——
两边都调 `Card.GetFinalDamage() / GetFinalShield() / RageManager.GetRageForCard()`，
这样「卡面写 146、实际打 146」永远成立（§6.2 的教训）。
状态修正只作用在**实例层**（战斗里 buff 改了这张卡的费用），策划表本身不被污染。

### 7.2 状态修正：buff 怎么改费用 / 增减词缀

策划表里声明「这张卡会被哪些 buff 影响、怎么影响」：

```json
"modifiers": [
  { "source": "buff:discount", "target": "cost",   "op": "add", "value": -1 },
  { "source": "buff:inspire",  "target": "affix",  "op": "add", "value": "retain" },
  { "source": "buff:weak",     "target": "damage", "op": "mul", "value": 0.8 }
]
```

- `target`：cost / affix / damage / shield / rage
- `op`：add（加）/ mul（乘）/ set（设）
- 实例化时把**当前生效的 buff** 套上去 → 得到这张卡在本场战斗的真实值

> 这套还没实现（现在没有「buff 改卡牌费用」的机制），
> 但**先把字段位留出来**，以后加 buff 不用改表结构。

### 7.3 效果列表：把「一个字段一个分支」换成数据驱动

**现状**（字段分支式）：`ApplyBuffName` / `ApplyDebuffName` / `IsAreaAttack` / `drawCountBase` /
`damagePercent` …… 每个字段在结算里各写一个分支。加一种新效果 = 改结算流程。

**目标**（效果列表式）：

```json
"effects": [
  { "type": "damage",   "percent": 80, "target": "allEnemies" },
  { "type": "shield",   "percent": 10, "target": "self" },
  { "type": "rage",     "value": 50 },
  { "type": "draw",     "count": 2, "filter": "lowestCostInstruction" },
  { "type": "buff",     "buff": "strength", "value": 3, "duration": 3, "target": "enemy" },
  { "type": "debuff",   "debuff": "poison",  "value": 2, "duration": 3, "target": "enemy" },
  { "type": "stack",    "stack": "罪印", "count": 3, "timing": ["onPlay", "onDiscard"] },
  { "type": "summon",   "cardId": "holy_heart", "count": 1, "to": "hand" },
  { "type": "buffNext", "buff": "苦痛救赎" }
]
```

**✅ 已实现（2026-10-24）** —— 引擎只做一件事：**遍历 effects → 按 type 分派到执行器**。
新增一种效果 = **加一个执行器 + 数据表加一行**，结算流程一行不改。

实现清单：`Scripts/Battle/Card/CardEffect.cs`（效果数据模型）、
`Scripts/Battle/Card/CardEffectEngine.cs`（执行器分派 + 数值计算）、
`Data/character_cards.json` 的 **65 张卡全部迁到 `effects[]`**（D41 又加了圣心，现共 **66 张**）。

已支持的效果类型：`damage`（可多次命中 / 可打全体）、`shield`、`rage`、`heal`、`energy`、
`draw`（可带筛选）、`buff`、`debuff`、`retain`（保留）、`consume`（消耗）。

**词缀（保留 / 消耗）在出牌回调里生效**（主人 2026-10-24：「应该是放在卡牌出完的回调函数里面吧，
你决定」→ 就放在 `BattleManager.OnCardPlayed` → `CardEffectEngine.Execute(..., onPlay)`）：
`retain` 在打出时置 `IsRetain`（回合结束留在手牌），`consume` 让这张卡**不进弃牌堆**。

`timing` 是关键：`onPlay`（打出）/ `onDiscard`（弃牌阶段后）——
灵知觉醒那句「打出时**和弃牌阶段后**获得 3 层罪印」就靠它表达。

### 7.4 「1-6 级的数值」怎么存（**这一条与主人说的略有不同，请核对**）

主人说的是「1-6 级的卡牌数值（属性、值的数组）」——
即**每一级的结果值都写进表里**。

我的建议改成：**存「基础百分比 + 等级系数」，1-6 级的值由公式算出来，另外允许每级覆盖**。

| | 主人说的（全部手填 6 个值） | 建议（公式 + 可覆盖） |
| :-- | :--- | :--- |
| 改一次等级系数 | 要同步改 65 张 × 6 = **390 个数** | 改 1 个常量 |
| 界面与战斗一致 | **要靠人保证**（手填的数和公式算的可能差 1） | **天然一致**（同一个函数） |
| 策划要精确控制 | 可以 | 用 `levelOverrides` 覆盖某一级 |

数据长这样：

```json
"damagePercent": 80,
"levelOverrides": { "6": { "damagePercent": 85 } }
```

**参考游戏自己也是公式驱动**（升级页右侧写的是「攻击力×20%」这种计算式），
所以我倾向公式 + 覆盖。✅ **主人 2026-10-24 拍板：「可以，还是使用公式」** ——
公式已落地（D37），并允许 `levelOverrides` 覆盖某一级。

### 7.9 卡面正文的词缀标注（`bodyAffixMarks`，D48）

参考游戏是**「两处都有」**：卡面正文**带**词缀标注（`⚠保留。` / `✕罪印` / `⚠灵知觉醒`），
同时右侧还有一块「词缀说明」区 —— 不是二选一。

| 字段 | 放哪 | 含义 |
| :--: | :--- | :--- |
| `bodyAffixMarks` | 卡牌自己的（同 `affixes` / `affixNotes` 一层） | **这张卡的正文要自动标哪些词缀** |

| 写法 | 语义 |
| :--- | :--- |
| **不写这个字段** | 默认：正文里**没提过**的词缀全部自动补（保留 / 消耗 / 回合唯一 + 卡牌特有词缀），符号取 `Data/affixes.json` 的 `symbol` |
| `[]` | **一个都不标** —— 正文完全由策划文案逐字负责 |
| `["prep1"]` | 只标这一个 |

**为什么要有这个字段**：参考图里圣心的正文末尾**只有「预备1。」、没有「⚠保留。」**，
但它的词缀说明区**列了保留** —— 「哪些词缀出现在正文里」是**逐卡不同**的，
光靠「没提过就自动补」这条通用规则补不出来（会把「保留」也补上去）。
做成数据表字段，以后遇到同类卡片**改一行 JSON 就能对齐参考图**，不用改代码。

⚠️ 实现上必须用 `null` 区分「没写字段」和「写了空数组」—— 见踩坑记录 §83。

**正文里已经出现过的词缀名不再重复标**（例：句中写了「✕罪印」，末尾就不必再标一次）。
