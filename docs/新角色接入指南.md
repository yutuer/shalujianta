## 一、wiki 能自动抓什么（不用截图）

灰机 wiki（`morimens.huijiwiki.com`）的**角色页**把机制层 / 数值层 / 文案层全部写成了结构化 wikitext，
用 `tools/wiki-character.ps1` 一条命令就能抓下来（2026-11-01 起不用再手抄）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\wiki-character.ps1 -Names 墨菲,珈伦
# 输出：<名>.wiki（原文）+ <名>.json（解析结果），落在系统临时目录，不污染仓库
```

| wiki 上能拿到 | 对应我们的什么 |
| :--- | :--- |
| 界域 / 唤醒体类型 / 稀有度 / 性别 / 英文名 / 生日 / 身高 / 体重 / 声优 | 角色档案（类型 → `Archetype`） |
| 本体数值 1/10/20/…/90 级 九档的 **体质 / 攻击 / 防御** | `BaseConstitution` / `BaseAttack` / `BaseDefense` |
| 升格 1~5（每条给 2 项属性的「旧值 → 新值」） | **属性 9 项里的 2 条**（见下方规则） |
| 启灵 1~15（名字 + 效果全文） | 被动 / 额外机制（本项目暂未实现） |
| 灵塑 1~10 + 固有天赋 + 内在灵格 | 天赋 / 命轮（本项目暂未实现） |
| 打击 / 防御 / 技能卡1 / 技能卡2 / 灵知觉醒 / 狂气爆发 / 特殊卡：**名字 / 算力 / 描述 / 6 级效果全文** | `Data/character_cards.json` + `Data/ultimates.json` 的 `effects[]` |
| 语音台词 / 故事 / 典藏馆故事 | 角色档案（未实现） |

> ⚠️ **wiki 上没有的角色**（本项目 12 个属相 BOSS 就没有页）只能走老流程 —— 主人给截图。
> 用 `tools/wiki-character.ps1 -Names xxx` 跑一下，报「页面里没有 `<pre>`」就是没有页。

### 属性合成规则（已用参考图逐项验证）

```
属性(9 项) = 通用值 + wiki 升格5(=60 级时) 那 2 条覆盖对应项
```

| 属性 | 通用值 | C# 字段 | wiki 属性名 |
| :--- | --: | :--- | :--- |
| 暴击率 | 5% | `BaseCritRate` | 暴击率 |
| 暴击伤害 | 50% | `BaseCritDamage` | 暴击伤害 |
| 界域精通 | 0 | `BaseDomainMastery` | 界域精通 |
| 伤害强效 | 0 | `BaseDamageBonus` | 伤害强效 |
| 基础狂气 | 100 | `BaseMaxRage` | 基础狂气 |
| 狂气回充等级 | 0 | `BaseRageReturn` | 狂气回充等级 |
| 银钥充能等级 | 15 | `BaseSilverKeyCharge` | 银钥充能等级 |
| 黑印掉落 | 0 | `BaseBlackMarkDrop` | 黑印掉落 |
| 死亡抵抗 | 0 | `BaseDeathResistance` | 死亡抵抗 |

**验证结果**（参考图「详细属性」面板 vs 规则输出）：
- **波吕克斯 9/9 全中** —— 通用值 7 项 + 升格5 给的 暴击率 14.6% / 伤害强效 4.8%
- **珈伦 9/9 全中** —— 通用值 7 项 + 升格5 给的 狂气回充 5.6 / 死亡抵抗 28，
  再叠加**珈伦特有的额外 10 命**（狂气回充 +4.8 / 死亡抵抗 +8.4）→ 参考图的 10.4 / 36.4

> ⚠️ **本体 3 项（体质/攻击/防御）不在这个规则里**：wiki 给的是 60 级**裸值**，
> 参考图显示的是**含内在灵格等额外加成**的当前值（波吕克斯 182/156/162 vs wiki 140/158/135）。
> 这一层口径**仍待主人拍板**，本轮先不动（动了会连带改掉所有卡牌数值）。

## 二、仍需主人提供的截图（只有 2 类）

wiki 给得了**机制 / 数值 / 文案**，给不了**视觉**。所以只缺这两类：

| # | 文件名 | 从图里能读出什么 | 缺了会怎样 |
| :--: | :--- | :--- | :--- |
| 1 | **视觉层截图**：`人物列表_<名>.jpg` + 每张卡的卡面图 | 游戏内角色一览的**排版 / 类型标签样式**、卡面**正文排版 + 词缀着色 + 费用与等级布局**、立绘 | UI 只能自己设计，跟参考游戏长得不一样 |
| 2 | `卡牌总览(满级)_<名>.jpg` | 5 张卡 + 狂气爆发在**满级**下的**结果值**（伤害 37 / 护盾 32 / 治疗 56 …） | ⚠️ 这是**交叉验证的硬证据**：wiki 给公式（攻击力×20%），参考图给结果值，两者对上才算数值复现成功 |

> **数值反推方法**见 [`卡牌设计.md`](卡牌设计.md) §6.2（波吕克斯那 5 张卡 + 狂气爆发的实测表）——
> 同样的算法照搬到新角色即可。
>
> 有了 wiki 之后，流程变成：**wiki 抓公式 → 用角色属性算出结果值 → 对照第 2 类截图核对**。
> 第 2 类截图从「必须逐张截图」压缩成「只要 1 张总览」。

## 三、我这边要改的 6 处

| # | 文件 | 改什么 | 注意 |
| :--: | :--- | :--- | :--- |
| 1 | `Scripts/Battle/CharacterSystem/CharacterDefinition.cs` | **+1 个 `Create<名>()`**：属性 9 项 + 本体 3 项 + 卡组 id | ⚠️ **这里才是运行时真值** —— 战斗和角色一览都走 `CharacterDefinition.GetAllCharacters()`；`Data/characters.json` 里那套属性字段**目前没人读**（`CharacterConfigLoader` 只读攻击/防御等少数几项） |
| 2 | `Data/characters.json` | **+1 条**：characterId / name / nameEn / race / baseHealth / baseEnergy / baseDrawCount / baseAttack / baseDefense / baseConstitution / baseCritRate / baseCritDamage / attackCardId / defenseCardId / specialCardIds[3] / ultimateSkillId | `race` 可留空（12 生肖都空，波吕克斯是 `chaos`）；**立绘不用填** —— 代码按 `char_<characterId>.svg` 自动推导；属性字段与第 1 项保持一致（虽未被读取，但别留错值误导人） |
| 3 | `Data/character_cards.json` | **+5 条**：打击 / 防御 / 3 张专属 | 每张要有 `effects[]`（唯一真相源）、`affixes`、`cardType`、`damageBaseCoefficient` 等；**打击/防御必须各角色独立**（`check-card-data.ps1` 守着）；**效果公式可直接从 wiki 的 6 级效果原文翻译**（`攻击力×20%` → `{"type":"damage","damagePercent":20}`） |
| 4 | `Data/ultimates.json` | **+1 条**：skillId / characterId / name / nameEn / description / rageCost / damagePercent(或 damage) / damageBaseCoefficient / isAreaAttack | 百分比口径：伤害 = 角色攻击 × 百分比，**不乘等级系数** |
| 5 | `tools/generate-card-art.ps1` | `$AllPalette` + `$charOrder` 各加一条（角色配色） | 脚本**默认不覆盖已存在文件** → 跑一次只会补生成新角色的 5 张卡插画 + 圆形头像 |
| 6 | `tools/generate-placeholder-svg.ps1` | `$Characters` 加一条（立绘造型/配色） | 这张表是**硬编码**的，不加就不会有 `char_<id>.svg` |

跑完脚本后要 `Godot.exe --headless --path <项目> --import` 生成 `.import`（否则运行时 No loader found）。

> **属性从哪来**：用 `tools/wiki-character.ps1` 抓 wiki → 按 §一 的规则合成 9 项 →
> 填进第 1 项（C# 硬编码，运行时真值）和第 2 项（json）。
> ⚠️ `BaseCritRate` 是 **float**（参考图给的是 14.6% 这种小数，int 存不下会变成 15）。

## 四、校验与实测

**数据层**
```powershell
powershell -ExecutionPolicy Bypass -File tools\check-card-data.ps1      # 每角色 2 张独立基本卡 / effects[] 一致
powershell -ExecutionPolicy Bypass -File tools\check-doc-consistency.ps1
powershell -ExecutionPolicy Bypass -File tools\check-task-stats.ps1
```

**运行时**（godot-runtime MCP，`background: true`）
- 角色一览**列表页**：新角色出现在网格里，名字 / 类型 / 头像正确
- 角色一览**详情页**：立绘 / 属性 / 5 张卡等级 / 天赋
- **卡牌总览页**：狂气爆发说明（数值与战斗同源）+ 5 张卡正文 + 词缀着色
- **战斗**：进战斗 → 队伍里有他 → 打出卡 → 数值与卡面一致（**卡面写 37 实际就得打 37**）

**提交前必还原**
- `Scripts/Dev/DevScenario.cs` 的 `presetKey` 改回 `"default"`
- `git checkout -- project.godot`（MCP 会注入 `McpBridge` autoload）
