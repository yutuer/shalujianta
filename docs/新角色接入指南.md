## 一、wiki 能自动抓什么（不用截图）

灰机 wiki（`morimens.huijiwiki.com`）的**角色页**把机制层 / 数值层 / 文案层全部写成了结构化 wikitext，
用 `tools/wiki-character.ps1` 一条命令就能抓下来（2026-11-01 起不用再手抄）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\wiki-character.ps1 -Names 墨菲,珈伦
# 输出：<名>.wiki（原文）+ <名>.json（解析结果），落在系统临时目录，不污染仓库
```

| wiki 上能拿到 | 对应我们的什么 |
| :--- | :--- |
| 界域 / 唤醒体类型 / 稀有度 / 性别 / 英文名 / 生日 / 身高 / 体重 / 声优 | 角色档案（类型 → `Archetype`） |
| 本体数值 1/10/20/…/90 级 九档的 **体质 / 攻击 / 防御** | `BaseConstitution` / `BaseAttack` / `BaseDefense` |
| 升格 1~5（每条给 2 项属性的「旧值 → 新值」） | **属性 9 项里的 2 条**（见下方规则） |
| 启灵 1~15（名字 + 效果全文） | 被动 / 额外机制（本项目暂未实现） |
| 灵塑 1~10 + 固有天赋 + 内在灵格 | 天赋 / 命轮（本项目暂未实现） |
| 打击 / 防御 / 技能卡1 / 技能卡2 / 灵知觉醒 / 狂气爆发 / 特殊卡：**名字 / 算力 / 描述 / 6 级效果全文** | `Data/character_cards.json` + `Data/ultimates.json` 的 `effects[]` |
| 语音台词 / 故事 / 典藏馆故事 | 角色档案（未实现） |

> ⚠️ **wiki 上没有的角色**（本项目 12 个属相 BOSS 就没有页）只能走老流程 —— 主人给截图。
> 用 `tools/wiki-character.ps1 -Names xxx` 跑一下，报「页面里没有 `<pre>`」就是没有页。

### ⚠️ 卡牌数据在角色页的「技能」小节里（不在独立卡牌页）

D60 实测踩到的坑（§109）。角色页 wikitext 的结构：

| wiki 小节 | 对应本项目的卡 |
| :--- | :--- |
| `打击` | 基本卡 1（打击） |
| `防御` | 基本卡 2（防御） |
| `技能1（右）` | 专属卡 1 |
| `技能2（左）` | 专属卡 2 |
| `灵知觉醒` | 专属卡 3（`cardType = awakening`） |
| `狂气爆发` | 狂气爆发 |

每张卡有 `效果1 ~ 效果6` **六档**，分别对应 1~6 级。

**⚠️ wiki 写的是 6 级说明 → 要换算成本项目的 1 级口径**：

| wiki 写法 | ❌ 别这么做 | ✅ 应该这么做 |
| :--- | :--- | :--- |
| 「防御力×48%」（6 级） | 把 48 填进 `shieldPercent` | 填 **24**（= 48÷2）→ 等级系数 ×2 → 面板 6 级还原成 48% |
| 「攻击力×20%」（6 级） | 把算好的绝对值 20 填进 `damage` | 填 `damagePercent: 10` → L6 = 攻击力×20% |
| 「获得 50 点狂气」（6 级） | 手填 `value: 50` | 走既有公式 `25 + 5×(级−1)` → L1 = 25 / L6 = 50 |
| 「获得 20 点狂气」（6 级，固定值） | 手填 20 | 固定值卡用 `value: 15, perLevel: 1` → L1 = 15 / L6 = 20 |

> ⚠️ **「把算好的绝对值填进 JSON」= 数值被钉死**，不再随等级成长。
> ⚠️ **wiki 的百分比永远是「攻击力/防御力 × N%」**，不是绝对值。
> ⚠️ **面板显示 = Level 6、战斗实际 = Level 1**（§104 既有约定）→ 面板上的数才是 wiki 的 6 级值。

### ⚠️ 专属卡的**顺序**也是显示契约（不是 wiki 的列出顺序）

参考游戏《终末前夜》的「技能」页里，**灵知觉醒卡永远排在 5 张卡的正中间（第 3 张）**：

```
打击 / 防御 / 凸月之舞(灵知觉醒) / 蟾蜍炖菜 / 静默守望      ← 珈伦参考图
        ↑ 第 3 张
```

而 wiki 上珈伦是「技能卡1 = 蟾蜍炖菜 / 技能卡2 = 静默守望 / 灵知觉醒 = 凸月之舞」——
**wiki 把灵知觉醒列成独立小节，游戏里它却占第 3 位，技能卡 1/2 顺延到 4/5 位。**

→ 本项目的显示顺序 = `specialCardIds[]` 的**数组顺序**
（`CharacterGallery.GetDeckCardIds` = 打击 + 防御 + `specialCardIds[]` 原序）
→ **填表时 `specialCardIds[0]` 必须放灵知觉醒卡**（`tools/check-card-data.ps1` 的规则 5b 会拦）。

### 属性合成规则（主人 2026-11-01 定案：wiki「60 级 0 命」）

```
属性(9 项) = 通用值 + wiki 升格5(=60 级时) 那 2 条覆盖对应项
```

> ⚠️ **口径定案（主人 2026-11-01）**：
> 「先不要管命座的值, 只使用 **60 级 0 命**的数据. 因为现在 wiki 的数值应该有点落后于游戏,
> 但是先不管, 使用 wiki 的数值来, 这样以后如果能找到其他正确数值的数据, 也好更新」
> → **数据源 = wiki「60 级 0 命」**。**参考图从此只是「wiki 规则是否成立」的验证证据，不是数值来源。**
> ⚠️ **wiki 数值可能落后于游戏**（主人明说先不管）—— 将来拿到更新的数据源时，**只改这一层**即可。

| 属性 | 通用值 | C# 字段 | wiki 属性名 | C# 类型 |
| :--- | --: | :--- | :--- | :--- |
| 暴击率 | 5% | `BaseCritRate` | 暴击率 | **float**（14.6 这类小数） |
| 暴击伤害 | 50% | `BaseCritDamage` | 暴击伤害 | int |
| 界域精通 | 0 | `BaseDomainMastery` | 界域精通 | int |
| 伤害强效 | 0 | `BaseDamageBonus` | 伤害强效 | **float**（4.8 这类小数） |
| 基础狂气 | 100 | `BaseMaxRage` | 基础狂气 | int |
| 狂气回充等级 | 0 | `BaseRageReturn` | 狂气回充等级 | **float**（5.6 这类小数） |
| 银钥充能等级 | 15 | `BaseSilverKeyCharge` | 银钥充能等级 | int |
| 黑印掉落 | 0 | `BaseBlackMarkDrop` | 黑印掉落 | **float** |
| 死亡抵抗 | 0 | `BaseDeathResistance` | 死亡抵抗 | int |

**规则是怎么被验证的**（参考图「详细属性」面板 vs 规则输出）：
- **波吕克斯 9/9 全中** —— 通用值 7 项 + 升格5 给的 暴击率 14.6% / 伤害强效 4.8%
- **珈伦 9/9 全中** —— 通用值 7 项 + 升格5 给的 狂气回充 5.6 / 死亡抵抗 28，
  再叠加**珈伦特有的额外 10 命**（狂气回充 +4.8 / 死亡抵抗 +8.4）→ 参考图的 10.4 / 36.4
  → ⚠️ **按定案口径，实际落地用的是 wiki 裸值 5.6 / 28**（不加 10 命）

> ⚠️ **本体 3 项（体质/攻击/防御）不在这个规则里**：wiki 给的是 60 级**裸值**，
> 参考图显示的是**含内在灵格等额外加成**的当前值（波吕克斯 182/156/162 vs wiki 140/158/135）。
> 这一层口径**仍待主人拍板**，本轮先不动（动了会连带改掉所有卡牌数值）。
> 珈伦的本体 3 项 wiki 裸值 112/96/108 与现值**本来就一致**，所以 D59 没动它。

> ⚠️ **小数属性一律用 float，且参与取整时要加 epsilon** ——
> `5.6f` 在 IEEE 754 单精度下的实际值是 **5.59999990463257**，
> 直接 `floor(100 × 5.6f / 10)` 会得到 **55**（应为 56）。
> 公式要写成「先转 double 算 + 加 1e-4」→ 见踩坑 **§107**。

### ⚠️ 实现不了的机制要**登记在数据里**，不能只写在文档里

D60 的做法（主人认可的口径：「**数据全落地 + 能实现的实现，新机制留 TODO 登记**」）：

每张卡 / 每条狂气爆发的 JSON 里加一个 `pendingMechanics[]` 数组，**写清「缺什么」**：

```json
"pendingMechanics": [
    "余波：获得等同于当前触腕数量的狂气（缺 ragePerStack 效果字段，现已写入但不会结算）",
    "获得 9 点力量（buff 效果目前只能挂在敌人身上，不能给自己）"
]
```

好处：下次有人扩引擎时**能直接 grep 到待办**，不用翻文档考古。

> ⚠️ **别硬凑近似** —— 比如把「给自己 +9 力量」近似成「给敌人 −9 防御」，
> 那是你替主人做的**平衡改动**，主人没要求。
> ⚠️ **⚠️ 卡面文案要留意**：wiki 原文照抄进 `description` 后，**没实现的句子在游戏里会「说假话」**
> （例：「获得等同于当前触腕数量的狂气」实际不发生）→ 要不要摘掉，**等主人拍板**（D60 遗留第 2 项）。
