### 参考图的统一视觉语言

1. **背景是实景插画**（甲板 / 走廊），有景深和暗角 —— 不是纯色面板。
2. **角色用立绘**（左下横排），不是方块头像。
3. **血条永远在立绘下方**，状态图标排（带层数数字）在血条下方。
4. **信息靠边**：顶部左头像、顶部右资源、右上统计、底部手牌、中央留空给演出。
5. **数字是大字**（总伤害 8485、血量 2081/2081），不是小标签。
6. 冷色调 + 描边 + 斜线/噪点纹理，图标是**有棱角的水晶形状**而不是圆形。

## 2. 现状诊断

### 2.1 当前场景结构

`
BattleScene (Node2D)
├─ Background (ColorRect)            纯色 (0.15,0.17,0.2) —— 无美术
├─ CardLayoutManager (Node)          手牌扇形布局参数
└─ UI (CanvasLayer)
   ├─ TopBar (HBoxContainer)         标题 + 楼层 + 怒气值 + 4 个空卡槽（画着 ×）
   ├─ ArtifactDetailUI
   ├─ MainArea (VBoxContainer)
   │  ├─ BattleZones (HBoxContainer)
   │  │  ├─ PlayerZone (Panel)       ← 默认灰框，左边一大块空
   │  │  │  └─ VBox: 玩家 / 圆圈(0/1000) / 血条 / 125/125 / 护盾0 / 能量10/10
   │  │  └─ EnemyZone (Panel)        ← 默认灰框
   │  │     └─ EnemyContainer (HBox) 3 个敌人小卡片挤在右上角
   │  └─ Spacer
   ├─ HandArea (Panel)                ← 默认灰框，压住手牌
   │  └─ HandContainer → HandCardPreview (扇形，牌面窄、描述被截断)
   ├─ BottomBar (HBox)                结束回合 / 地图 / 钥令 / 测试  +  手牌:8 抽牌堆:12 弃牌堆:0
   ├─ BattleLogWindow (浮层)          450×350 固定尺寸，压在手牌区上方
   └─ CommonHUD                       银光斩 + 4 个空槽 + 攻击体编队 + 4 个资源数字
`

### 2.2 「太乱」的四个根因

| # | 根因 | 现象 |
| :--- | :--- | :--- |
| **A** | **没有空间分区概念** | 所有东西靠 `VBox` / `HBox` 流式串联，没有「这块归谁」的锚定分区 → 元素随内容长度漂移 |
| **B** | **同一信息出现在 3 个地方** | 角色血量在 `AttackerDisplayUI`（左上「鼠 0/100 0%」）、`CommonHUD`（右上「生命 125/125」）、`PlayerZone`（「125/125」）各写一遍 |
| **C** | **默认 Panel 灰框把画面切成三块** | `PlayerZone` / `EnemyZone` / `HandArea` 三个 `Panel` 的默认边框形成割裂的「三个抽屉」 |
| **D** | **纯色背景 + 无立绘** | 中间大片空黑（玩家区）没有任何内容锚点，视觉上就是「没做完」 |

外加几个具体毛病：手牌描述被截断成「使用特…」「使」；战斗日志浮窗压住手牌；底部「测试」调试按钮和正式按钮混排；顶部那排画着 `×` 的空卡槽用途不明。

## 4. 改造原则（硬约束）

1. **逻辑进 `.cs`、布局进 `.tscn`** —— 每个新分区建独立 `.tscn`，不在代码里硬编码坐标。
2. **一个 `.cs` 一个类**；`.tscn` 根节点必须绑 script。
3. **事件回调首尾必须 `GD.Print(... called/completed)`**。
4. **改完必须 `dotnet build` 0 错**。
5. **不动战斗逻辑** —— 本轮只改「看得见的部分」，回合/伤害/状态机一律不碰。
6. **不删功能** —— 「测试」按钮可以移到别处，但不能消失。
